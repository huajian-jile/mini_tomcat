1️⃣ Server vs Service
Server（服务器）
// 代表整个 Tomcat 实例，是最高级别的容器
public class Server implements Lifecycle {
private final List<Service> services = new ArrayList<>();

    // 管理所有 Service 的生命周期
    public void init() { for (Service s : services) s.init(); }
    public void start() { for (Service s : services) s.start(); }
    public void stop() { for (Service s : services) s.stop(); }
}
作用：管理整个服务器生命周期，持有多个 Service

Service（服务）
// 将多个 Connector 与一个 Engine 关联
public class Service implements Lifecycle {
private final Engine engine = new Engine();           // 一个 Engine
private final List<Connector> connectors = new ArrayList<>();  // 多个 Connector

    public void addConnector(Connector c) {
        c.setContainer(engine);  // 把 Engine 交给 Connector
        connectors.add(c);
    }
}
作用：把端口监听（Connector）和请求处理（Engine）绑在一起

区别
Server	Service
层级	最高，整个 Tomcat	中间层
包含	多个 Service	多个 Connector + 一个 Engine
作用	统一管理生命周期	把端口和处理逻辑绑在一起
2️⃣ Connector（连接器）vs Engine（引擎）
Connector - "门卫"
// 监听端口，接受 HTTP 请求
public class Connector implements Lifecycle {
private int port = 9000;
private Container container;  // 这里指向 Engine

    public void start() {
        serverSocket = new ServerSocket(port);  // 监听端口
        while (running) {
            Socket socket = serverSocket.accept();  // 接受请求
            // 把请求封装成 Request，交给 container (Engine) 处理
            container.invoke(request, response);
        }
    }
}
职责：

监听端口（9000、8080 等）
接收 HTTP 请求
封装成 Request 对象
交给 Container 处理
写出 Response
Engine - "中枢"
// 核心处理引擎
public final class Engine implements Container {
private final List<Host> hosts = new ArrayList<>();  // 多个虚拟主机
private final Pipeline pipeline = new PipelineBase();

    public void invoke(Request request, Response response) {
        pipeline.invoke(request, response);  // 通过 Pipeline 处理
    }
}
职责：

管理虚拟主机（Host）
选择用哪个 Host 处理请求（根据 Host 头）
是请求处理的中枢
对比
Connector	Engine
角色	门卫/翻译官	调度中心
位置	网络层 ↔ 容器层	容器层顶层
做什么	接受请求、封装、写出响应	决定哪个 Host 处理
3️⃣ 容器层级（Container Hierarchy）
Tomcat 用 责任链模式 + 组合模式 处理请求：

Engine (引擎)
│  按 Host 头选择
▼
Host (虚拟主机)
│  按 URL 路径选择
▼
Context (Web 应用)
│  按 Servlet 映射选择
▼
Wrapper (Servlet)
请求处理流程（以 http://localhost:9000/app/hello 为例）
1. Connector 接收请求
   │
   ▼
2. Engine.invoke() → Pipeline
   │
   ▼
3. EngineValve: 读取 Host 头 → 选择 localhost
   │
   ▼
4. Host.invoke() → Pipeline
   │
   ▼
5. HostValve: 读取 URL → 选择 /app 这个 Context
   │
   ▼
6. Context.invoke() → Pipeline
   │
   ▼
7. ContextValve: 读取 /hello → 选择 HelloServlet
   │
   ▼
8. Wrapper: 实例化/调用 Servlet.service()
   4️⃣ Pipeline + Valve（责任链）
   每层容器都有 Pipeline，里面装 Valve：

public interface Valve {
void invoke(Request request, Response response, Valve next);
}
好处：可以在任意阶段插入处理逻辑（比如日志、权限检查）

1️⃣ 为什么只设置 Engine？不传 Host、Context？
// Service.java
public void addConnector(Connector connector) {
connector.setContainer(engine);  // 只传 Engine
connectors.add(connector);
}
原因：

Engine 是容器层级的最顶层
传了 Engine 之后，后续的 Host、Context、Wrapper 会通过 Pipeline/Valve 链 自动层层传递
没必要传具体的 Host/Context，因为请求 URL 不同，匹配的 Context 就不同
Connector.setContainer(engine)  // 传顶层
│
▼
Engine.invoke() → 内部用 EngineValve 选择 Host
│
▼
Host.invoke()   → 内部用 HostValve 选择 Context
│
▼
Context.invoke() → 内部用 ContextValve 选择 Wrapper(Servlet)
2️⃣ 为什么要接受多个端口？
// 一个 Service 可以加多个 Connector
service.addConnector(new Connector(8080));
service.addConnector(new Connector(8443));  // HTTPS
service.addConnector(new Connector(8009));  // AJP
场景：

端口	用途
8080	普通 HTTP
8443	HTTPS
8009	AJP（和 Apache/Nginx 通信）
不管哪个端口进来，都交给 同一个 Engine 处理，这样逻辑统一。

3️⃣ 为什么 container.invoke() 没传 Socket？
这是个好问题！看代码：

// Connector.java - process() 方法
private void process(Socket socket) {
// 1. 从 Socket 拿到 InputStream/OutputStream
InputStream in = socket.getInputStream();
OutputStream out = socket.getOutputStream();

    // 2. 封装成 Request/Response（此时已经不需要 Socket 了！）
    Request request = new Request(in);
    Response response = new Response(out);
    
    // 3. 容器只处理 Request/Response，不关心 Socket
    container.invoke(request, response);
    
    // 4. Socket 的生命周期在 Connector 这里管理
    response.flush();
    socket.close();  // 用完关闭
}
Socket 是网络层的东西，容器只关心 HTTP 层面的 Request/Response。

┌─────────────────────────────────────────────────────────┐
│                    Connector                            │
│  Socket ──► InputStream ──► Request                    │
│           OutputStream ◄─── Response                   │
│                                                         │
│  container.invoke(request, response)  ← 容器只拿这些   │
└─────────────────────────────────────────────────────────┘
│
▼
┌─────────────────────────────────────────────────────────┐
│                    Engine/Host/Context                  │
│  只处理 Request/Response， Socket 在 Connector 手里      │
└─────────────────────────────────────────────────────────┘
4️⃣ 完整请求链路（再捋一遍）
以 http://localhost:8080/app/hello 为例：

1. ServerSocket.accept() → 收到 Socket
   │
2. new Request(InputStream) → 解析 HTTP 请求行、头
   │
3. container.invoke(request, response) → 交给 Engine
   │
4. Engine.Pipeline.invoke() → EngineValve 执行
   │
5. 读取 request.getHeader("Host") → 选择 Host(localhost)
   │
6. Host.Pipeline.invoke() → HostValve 执行
   │
7. 读取 request.getUri() = "/app/hello" → 选择 Context(/app)
   │
8. Context.Pipeline.invoke() → ContextValve 执行
   │
9. 匹配 Servlet 映射 → 选择 Wrapper(HelloServlet)
   │
10. wrapper.getServlet().service(request, response)
    │
11. Response 写出到 OutputStream
    │
12. socket.close() → 关闭连接
    总结
    问题	答案
    为什么只传 Engine？	Engine 是顶层，下层会通过 Valve 链自动选择
    为什么要多端口？	不同协议/用途，统一交给 Engine 处理
    为什么不传 Socket？	Socket 是网络层，容器只处理 Request/Response
