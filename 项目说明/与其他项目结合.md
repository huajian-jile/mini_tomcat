区别如下：

项目	服务器实现	端口	说明
minispring 单独启动	JDK 内置的 com.sun.net.httpserver.HttpServer	8099	Java SE 自带的轻量级 HTTP 服务器
mini_tomcat 启动	自定义 java.net.ServerSocket	9000	自己从头实现的 HTTP 服务器
单独启动 minispring 的影响：

可以正常运行，功能完全一样
只是端口变成 8099
使用 JDK 内置的 HTTP 服务器（简单但功能有限）
mini_tomcat 启动：

使用自定义的 ServerSocket
完整的 Servlet 容器实现
支持静态资源、Servlet、Filter 等
可以部署多个应用
现在 mini_tomcat 已经整合了 minispring，通过 /api/* 路径访问 minispring 的 API，其他路径访问静态资源。



目录结构
mini_tomcat/
├── minispring/                    # 部署的 Web 应用
│   ├── WEB-INF/                  # Web 应用配置目录
│   │   ├── classes/              # 编译后的 class 文件
│   │   │   └── liu/              # minispring 的所有类
│   │   └── lib/                  # 依赖 jar 包
│   │       ├── cglib.jar
│   │       └── mysql.jar
│   └── servlet/                  # 我创建的适配器（关键！）
│       ├── MiniSpringServlet.java    # Servlet 入口
│       └── MiniSpringExchange.java   # 请求/响应适配器


WEB-INF/	Web 应用标准目录，Tomcat 规范
WEB-INF/classes/	存放编译后的 .class 文件
WEB-INF/lib/	存放依赖的 jar 包
servlet/MiniSpringServlet.java	核心 - 把 mini_tomcat 的请求转发给 minispring
servlet/MiniSpringExchange.java	核心 - 适配两种不同的请求/响应接口


可以删除吗？
不能删除！ 这两个 servlet 文件是连接 mini_tomcat 和 minispring 的桥梁：

没有它们 → mini_tomcat 无法调用 minispring 的代码
以后部署项目
是的，可以用类似方式部署：

把编译后的 class 文件放到 WEB-INF/classes/
把依赖 jar 放到 WEB-INF/lib/
如果需要自定义 Servlet 映射，在 Main.java 中添加 Wrapper
不过更好的方式是创建标准的 WEB-INF/web.xml 配置文件来管理 Servlet 映射，这样更像真正的 Tomcat 部署方式。
