# Mini Tomcat 部署指南

本文档说明如何将你的后端项目部署到 Mini Tomcat 中运行。

---

## 一、Web 应用目录结构

Mini Tomcat 采用与 Tomcat 相同的 **WAR 标准布局**：

```
webapp/                    ← docBase，应用根目录
├── index.html             ← 可直接访问的静态文件
├── css/
├── js/
├── images/
└── WEB-INF/               ← 私有目录，客户端不可直接访问
    └── web.xml            ← 部署描述符（必须）
```

- **根目录及子目录**：存放 HTML、CSS、JS、图片等静态资源，可通过 URL 直接访问
- **WEB-INF/**：仅服务器可读，用于配置和类文件
- **web.xml**：配置 Servlet、Filter、欢迎页等

---

## 二、两种部署方式

### 方式 A：直接使用内置 webapp 目录（推荐入门）

把你的项目内容放入 Mini Tomcat 的 `webapp/` 目录：

1. 静态资源：放到 `webapp/` 根目录或子目录
2. 配置：编辑 `webapp/WEB-INF/web.xml`
3. Servlet/Filter 类：放入项目 `src`，编译到 `out`，与 Main 一起运行

启动时工作目录为项目根目录，Mini Tomcat 会自动找到 `webapp` 并加载 `web.xml`。

### 方式 B：使用独立项目目录（推荐正式部署）

你的后端项目单独一个目录，例如 `myapp/`，结构如下：

```
myapp/
├── index.html
├── WEB-INF/
│   ├── web.xml
│   └── classes/          ← 你的 Servlet/Filter 编译后的 class
│       └── com/your/pkg/
│           └── HelloServlet.class
└── ...
```

需要**修改 Main.java**，将 docBase 指向你的项目目录，例如：

```java
// 在 Main.java 中，将 resolveWebappDir() 的返回值改为你的项目路径
context.setDocBase("D:/projects/myapp");  // 或通过启动参数、配置文件传入
```

并确保启动时 classpath 包含你的 `WEB-INF/classes` 或打包后的 JAR。

## 三、开发 Servlet（后端接口）

### 3.1 实现接口

你的 Servlet 必须实现 **`minitomcat.servlet.Servlet`**：

```java
package com.example;

import minitomcat.servlet.Servlet;
import minitomcat.http.Request;
import minitomcat.http.Response;

public class HelloServlet implements Servlet {
    @Override
    public void service(Request request, Response response) throws Exception {
        response.setContentType("text/html; charset=UTF-8");
        response.setBody("<h1>Hello " + request.getParameter("name") + "</h1>");
    }
}
```

### 3.2 在 web.xml 中注册

```xml
<servlet>
    <servlet-name>hello</servlet-name>
    <servlet-class>com.example.HelloServlet</servlet-class>
    <init-param>
        <param-name>greeting</param-name>
        <param-value>Hi</param-value>
    </init-param>
</servlet>
<servlet-mapping>
    <servlet-name>hello</servlet-name>
    <url-pattern>/hello</url-pattern>
</servlet-mapping>
```

### 3.3 常用 API

| 用途 | 方法 |
|------|------|
| 请求方法 | `request.getMethod()` |
| 请求路径 | `request.getUri()`, `request.getServletPath()` |
| 请求参数 | `request.getParameter(name)`, `request.getParameterMap()` |
| 请求头 | `request.getHeader(name)` |
| 请求属性 | `request.setAttribute()`, `request.getAttribute()` |
| Session | `request.getSession()` |
| 上下文参数 | `request.getContext().getContextParam(name)` |
| 响应状态 | `response.setStatus(404, "Not Found")` |
| 响应类型 | `response.setContentType("application/json")` |
| 响应体 | `response.setBody(string)` 或 `response.setBody(byte[])` |
| 响应头 | `response.addHeader(name, value)` |

## 四、开发 Filter

```java
package com.example;

import minitomcat.filter.Filter;
import minitomcat.filter.FilterChain;
import minitomcat.http.Request;
import minitomcat.http.Response;

public class LogFilter implements Filter {
    @Override
    public void doFilter(Request request, Response response, FilterChain chain) throws Exception {
        System.out.println("Request: " + request.getMethod() + " " + request.getUri());
        chain.doFilter(request, response);
    }
}
```

web.xml：

```xml
<filter>
    <filter-name>log</filter-name>
    <filter-class>com.example.LogFilter</filter-class>
</filter>
<filter-mapping>
    <filter-name>log</filter-name>
    <url-pattern>/*</url-pattern>
</filter-mapping>
```

## 五、类路径与启动

### 5.1 目录布局（方式 A）

假设你的 Servlet 在 `com.example` 包下：

```
mini_tomcat/
├── src/
│   ├── Main.java
│   ├── minitomcat/...
│   └── com/example/           ← 你的代码
│       └── HelloServlet.java
├── out/                       ← 编译输出
│   ├── Main.class
│   ├── minitomcat/...
│   └── com/example/
│       └── HelloServlet.class
└── webapp/
    └── WEB-INF/
        └── web.xml
```

### 5.2 编译

```bash
javac -encoding UTF-8 -sourcepath src -d out src/Main.java src/com/example/HelloServlet.java
```

或编译整个 src 目录：

```bash
javac -encoding UTF-8 -sourcepath src -d out src/**/*.java
```

### 5.3 启动

```bash
java -cp out Main
```

确保工作目录为项目根目录（含 `webapp` 的目录），或 `out` 的父目录。

### 5.4 使用外部 JAR

若你的项目依赖第三方 JAR：

```bash
java -cp "out;lib/*" Main
```

（Windows 用 `;`，Linux/Mac 用 `:`）

## 六、web.xml 配置参考

```xml
<?xml version="1.0" encoding="UTF-8"?>
<web-app version="4.0" xmlns="http://xmlns.jcp.org/xml/ns/javaee"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://xmlns.jcp.org/xml/ns/javaee 
         http://xmlns.jcp.org/xml/ns/javaee/web-app_4_0.xsd">

    <!-- 应用级参数，Servlet 通过 request.getContext().getContextParam(name) 获取 -->
    <context-param>
        <param-name>dbUrl</param-name>
        <param-value>jdbc:mysql://localhost/mydb</param-value>
    </context-param>

    <!-- Filter -->
    <filter>
        <filter-name>charset</filter-name>
        <filter-class>minitomcat.filter.CharsetFilter</filter-class>
    </filter>
    <filter-mapping>
        <filter-name>charset</filter-name>
        <url-pattern>/*</url-pattern>
    </filter-mapping>

    <!-- 欢迎页（访问 / 时依次尝试） -->
    <welcome-file-list>
        <welcome-file>index.html</welcome-file>
    </welcome-file-list>

    <!-- Servlet -->
    <servlet>
        <servlet-name>api</servlet-name>
        <servlet-class>com.your.ApiServlet</servlet-class>
        <init-param>
            <param-name>debug</param-name>
            <param-value>true</param-value>
        </init-param>
    </servlet>
    <servlet-mapping>
        <servlet-name>api</servlet-name>
        <url-pattern>/api/*</url-pattern>
    </servlet-mapping>

    <!-- 默认 Servlet：处理静态资源，必须保留 -->
    <servlet>
        <servlet-name>default</servlet-name>
        <servlet-class>minitomcat.servlet.DefaultServlet</servlet-class>
    </servlet>
    <servlet-mapping>
        <servlet-name>default</servlet-name>
        <url-pattern>/</url-pattern>
    </servlet-mapping>
</web-app>
```

### url-pattern 说明

| 模式 | 示例 | 匹配 |
|------|------|------|
| `/` | 默认 Servlet | 所有路径 |
| `/hello` | 精确 | 仅 `/hello` |
| `/api/*` | 前缀 | `/api/x`、`/api/user/1` 等 |

## 七、快速检查清单

- [ ] 项目结构符合 WAR 布局，根目录有 `WEB-INF/web.xml`
- [ ] Servlet 实现 `minitomcat.servlet.Servlet`，Filter 实现 `minitomcat.filter.Filter`
- [ ] web.xml 中 servlet-class、filter-class 使用**全限定类名**
- [ ] 编译后的 class 在 classpath 中（与 Main 一起运行）
- [ ] 启动时工作目录正确，或 Main 中 docBase 指向你的应用目录
- [ ] 保留 default Servlet 映射到 `/`，否则静态资源无法访问

## 八、常见问题

**Q：访问 404？**  
检查 url-pattern 是否匹配、servlet-class 是否正确、class 是否在 classpath。

**Q：静态文件访问不到？**  
确保 web.xml 中有 default Servlet 映射到 `/`，且 docBase 指向包含静态文件的目录。

**Q：如何支持 JSON API？**  
在 Servlet 中 `response.setContentType("application/json")`，`response.setBody(jsonString)`。

**Q：如何读取 POST JSON body？**  
当前 Request 只解析 `application/x-www-form-urlencoded`。需要 JSON 时，可从 `request.getInputStream()` 读取原始字节后自行解析。
